# Foundations

[디자인 개요](../DESIGN.md) · [시스템 구조](system.md) · [컴포넌트](components.md) · [사용 패턴](patterns.md)

색상·서체·간격·깊이·형태 등 공통 시각 재료의 기준이다. 실제 값은 [디자인 토큰](design-tokens.json)을 기준으로 한다.

제공 시안의 블루 방향을 유지하면서 넓은 표면의 색상 강도를 낮춘다. 주요 동작·현재 위치·링크에는 명확한 블루를 사용하고, 배경과 데이터 채움은 더 부드럽게 구분한다.

## Colors

### Primary

기준 블루는 **#3B6FD8**다. `color.brand.primary`는 브랜드 강조, `color.action.primary`는 주요 동작, `color.selection.border`는 필요한 선택 경계를 맡는다. 회색 기운으로 강조를 없애지 않으며, 역할이 없는 제목·아이콘까지 일괄적으로 블루로 칠하지 않는다. 같은 값을 참조하더라도 사용 의도를 구분한다.

주요 동작은 `primary → hover → pressed` 순서로 어두워진다. 글자는 `color.action.foreground`를 사용한다. 선택된 영역은 `color.selection.background`와 `color.selection.foreground`를 함께 사용하며, 체크·외곽선·텍스트 등 색상 이외의 선택 표시를 동반한다.

**역할 우선 규칙.** 주요 동작, 선택, 텍스트 등 용도에 맞는 역할 토큰을 사용한다. 같은 블루라도 역할이 다르면 별도의 의미를 유지한다.

### Secondary

짙은 블루는 필요한 브랜드 강조와 링크에 사용한다. 선택 배경은 옅은 블루를 기본으로 하고 체크·밑줄·글자 굵기 등으로 현재 상태를 표시한다. 링크에는 읽을 수 있는 `color.text.link`와 밑줄 등 추가 단서를 제공한다.

민트·시안·보라는 제공 시안의 장식 색상으로 보존한다. 민트는 성공을 뜻하지 않으며, 시안·보라 역시 상태를 뜻하지 않는다. 장식은 필요할 때만 사용하며 텍스트·표·그래프 뒤에서 가독성을 해치지 않는다. 그라데이션을 기본 표면으로 강제하지 않는다.

### Tertiary

안내는 중립색, 작업 성공은 채도를 낮춘 그린, 주의는 브라운 계열의 앰버, 오류는 채도를 낮춘 레드를 사용한다. 필요한 상태 안내에는 `background`와 `foreground`를 한 쌍으로 적용한다. 색 배경은 안내 범위에만 사용하고 일반 목록의 상태 열마다 반복하지 않는다.

‘완료’, ‘검토 중’ 같은 진행 단계는 성공·주의·오류 의미와 구분한다. 진행 단계의 기본 표현은 중립 텍스트이며, 단어마다 서로 다른 색 배지를 붙이지 않는다. 강조는 지금 사용자의 조치가 필요한 예외 상태에 사용한다.

데이터 색상 역시 초기 제안이며 다음 세 역할을 구분한다. 넓게 채워도 무겁지 않도록 브랜드 색상보다 밝고 채도가 낮은 별도 팔레트를 사용한다. 가장 높은 단계도 네이비까지 어둡게 만들지 않는다.

| 토큰 계열 | 의미 | 사용 규칙 |
|---|---|---|
| `color.data.categorical.1–6` | 순서 없는 범주 | 같은 범주에는 여러 화면에서 같은 색상 유지. 6개 초과 시 색상 추가보다 그룹화·분할 우선 |
| `color.data.sequential.1–5` | 낮음에서 높음으로 이어지는 양 | 옅음에서 짙음 순서 고정. 범례에 값 또는 구간 명시 |
| `color.data.diverging.*` | 기준점 양쪽의 응답·값 | 오렌지·중립·블루 순서 고정. 긍정·부정 의미를 범례로 명시 |
| `color.data.missing` | 결측 또는 무응답 | 중립 응답과 별도 범주로 표시. 라벨과 패턴 등 추가 구분 사용 |

**데이터 의미 규칙.** 값의 증가가 항상 성공이나 개선을 뜻하지 않는다. 임의로 그린·레드 상태색에 연결하지 않는다. 동일 값의 색상 의미는 화면마다 바꾸지 않는다.

**색상 단독 전달 금지 규칙.** 범례·직접 라벨·수치·선 모양·패턴 중 필요한 추가 단서를 함께 사용한다. 이 팔레트만으로 색각 다양성 대응이 완료된 것으로 간주하지 않는다. 옅은 데이터 색상은 흰 표면과 경계가 약하므로 직접 라벨이나 구분선 등 별도 식별 단서를 제공한다. 데이터 채움 위에 흰 글자를 일괄 배치하지 말고, 기본은 표면 위의 진한 외부 라벨로 둔다.

### Neutral

`surface.canvas`는 전체 바탕, `surface.default`는 기본 표면, `surface.subtle`은 보조 표면이다. 본문은 `text.primary`, 보조 설명은 `text.secondary`, 덜 중요한 설명과 placeholder는 `text.muted` 또는 `text.placeholder`를 사용한다.

`border.default`는 영역 구분용이다. 입력창이나 클릭 가능한 컨트롤의 유일한 경계에는 대비가 더 높은 `border.control`을 사용한다. 비활성 상태는 별도 토큰을 적용하고 실제 비활성 동작과 함께 제공한다.

입력 계열은 `color.field.background`·`foreground`·`border`·`border-hover`를 함께 사용한다. 텍스트 입력·검색·선택 상자·여러 줄 입력·대화 입력이 같은 표면과 상태 체계를 공유한다. 배경은 기본·호버·포커스·목록 열림에서 흰색을 유지한다. 옅은 회색은 조회 영역 등 보조 표면과 보조 동작을 구분하는 데 사용한다. 상세 상태는 [입력 규격](components.md#inputs-and-selects)을 따른다.

포커스는 `focus.ring` 색상의 2px 외곽선과 2px 간격을 사용한다. 텍스트와 배경의 대비는 4.5:1 이상, 컨트롤 경계·포커스와 인접 배경의 대비는 3:1 이상을 유지한다. 색상 조합은 실제 배경을 기준으로 판단한다.

## Typography

### Typeface

기본 서체는 **Pretendard**다. 제공 시안에서 가장 많이 사용된 서체이며, 한글·영문·숫자를 같은 서체로 통일한다. 기본 서체 부재 시 시스템 산세리프 계열을 사용한다.

시안 일부에 사용된 Inter와 Montserrat는 공통 본문 서체로 채택하지 않는다. 로고는 제공된 자산의 형태를 유지하며 본문 서체로 재작성하지 않는다. 아이콘용 글꼴은 본문 타이포그래피에 포함하지 않는다.

### Type Scale

시안에서 확인한 12·14·16·20·24px을 역할별로 정리한 공통 기준이다. 같은 역할은 화면마다 동일한 크기·굵기·행간을 사용한다. 아래 px은 기본 글자 크기 16px 기준이며, 사용자 글자 확대에 따라 함께 커지도록 한다. 서체는 `font.family.primary`, 크기·굵기·행간은 `type.{역할}.{size|weight|line-height}` 토큰을 사용한다.

| 역할 | 크기 | 굵기 | 행간 | 용도 |
|---|---|---|---|---|
| `type.title` | 1.5rem · 24px | 600 | 1.4 | 화면의 최상위 제목 |
| `type.section` | 1.25rem · 20px | 600 | 1.4 | 주요 영역 제목 |
| `type.subtitle` | 1rem · 16px | 600 | 1.5 | 하위 제목 |
| `type.body` | 1rem · 16px | 400 | 1.6 | 설명과 문단 본문 |
| `type.label` | 0.875rem · 14px | 500 | 1.5 | 버튼·입력 라벨·짧은 항목명 |
| `type.table` | 0.875rem · 14px | 400 | 1.5 | 밀도가 높은 표와 데이터 목록 |
| `type.caption` | 0.75rem · 12px | 400 | 1.5 | 보조 설명·단위·메타정보 |
| `type.value` | 1.5rem · 24px | 600 | 1.3 | 강조할 주요 수치 |

**굵기 절제 규칙.** 본문은 400, 라벨은 500, 제목과 주요 수치는 600을 기본으로 한다. 700은 문장 안의 짧은 핵심 강조에 제한한다. 화면 전체를 굵게 처리하지 않는다.

### Reading and Numbers

- 기본 자간은 0으로 둔다. 한글 본문의 자간을 임의로 좁히지 않는다.
- 긴 설명은 본문 크기와 충분한 행간을 사용한다. 작은 글씨는 짧은 보조 정보에만 사용하며, 시안의 10px 텍스트는 공통 기준으로 채택하지 않는다.
- 표의 숫자는 오른쪽 정렬하고, 비교할 숫자에는 고정폭 숫자 기능인 `tabular-nums`를 사용한다. 숫자 비교만을 위해 별도의 서체를 섞지 않는다.
- 같은 지표의 소수 자릿수와 단위 표기를 통일한다. 결측과 0은 다른 표기로 구분한다.
- 제목은 의미 단위로 자연스럽게 줄바꿈한다. 긴 문구나 글자 확대 때문에 핵심 내용이 잘리지 않도록 한다.
- 글자 강조는 크기·굵기·색상의 위계로 표현한다. 보조 정보도 읽을 수 있는 색상 대비를 유지한다.
- 사용자가 자주 읽는 도움말·적용 조건·결과 설명은 `type.table`의 14px 이상을 사용한다. `type.caption`의 12px은 짧은 단위·시점·예시 번호에 제한한다. 정보가 많다는 이유로 본문을 작은 글씨로 낮추지 않는다.
- 일반 안내는 짧은 해요체, 입력 라벨과 버튼은 간결한 명사·동작명으로 작성한다. 친근함은 이모지·과장된 인사보다 자연스러운 문장과 충분한 읽기 공간으로 표현한다.

## Spacing

간격은 **4·8·12·16·24·32·48px** 단계로 제한한다. 기본 글자 크기 16px 기준이며 실제 크기는 rem을 사용한다. 아이콘과 문구 사이는 [컴포넌트 크기표](components.md#shared-sizes)의 간격을 적용한다. 같은 그룹의 컨트롤 사이는 8px, 라벨과 입력창 사이는 8px, 서로 다른 필드 사이는 16px, 주요 영역 사이는 24px 또는 32px을 사용한다.

숫자보다 관계를 먼저 정한다. 같은 작업에 속하는 요소는 가깝게, 다른 작업 영역은 더 넓게 띄운다. 제목 위의 간격은 제목과 본문 사이보다 넓게 둔다. 내용이 짧은데 고정 높이로 빈 공간을 채우거나, 모든 요소에 같은 간격을 적용하지 않는다. 시작·진행·오류 상태에서 내용량이 달라질 때에도 이 관계를 유지한다.

| 관계 | 기본 간격 |
|---|---|
| 같은 그룹의 버튼·조건 | 8px |
| 라벨과 입력·제목과 짧은 설명 | 8px |
| 문단과 문단·필드와 필드 | 16px |
| 조건 영역의 내부 여백·독립 내용의 내부 여백 | 24px |
| 제목 영역과 본문·관련 내용 묶음 | 24px |
| 주요 섹션·대화 턴 | 32px |
| 화면 안쪽 여백 | 24px, 좁은 화면 16px |

컨트롤 옆에 좁은 간격으로 긴 설명을 붙이지 않는다. 관련 조건은 이름과 값을 가진 행으로 정리하며, 별도 작업은 32px 간격 또는 실제 영역 경계로 분리한다.

기본 단계는 `space.{px}`, 용도는 `space.layout.page`·`space.layout.section`·`space.field.stack`·`space.control.group`·`space.message.turn`으로 연결한다. 본문 최대 폭·읽기 폭·보조 패널 폭은 각각 `size.layout.content-max`·`size.layout.reading-max`·`size.layout.assistant`를 사용한다. 실제 배치 조건은 [사용 패턴](patterns.md#layout-and-density)에서 정의한다.

## Elevation & Depth

전체 바탕은 부드러운 중립 표면, 주요 작업 영역은 흰 표면으로 구분한다. 큰 작업 영역은 둥근 모서리로 정돈할 수 있으며 그 안의 세부 섹션은 제목·여백으로 구분한다. 섹션마다 카드와 그림자를 반복하지 않고, 표의 행이나 실제 경계가 필요한 곳에만 구분선을 사용한다.

조건 묶음·선택 도구·대화 같은 보조 작업은 옅은 중립 표면으로 역할을 구분할 수 있다. 모든 영역에 테두리를 둘러 구획하지 않는다. 흰 입력창이 옅은 표면 위에 놓이면 배경 차이와 얇은 컨트롤 경계로 조작 대상을 드러낸다. 패널의 역할이 분명하면 둥근 외곽선을 추가로 반복하지 않는다.

메뉴·팝오버에는 `shadow.popover`, 모달에는 `shadow.dialog`를 사용한다. 그림자는 떠 있는 요소의 깊이를 나타낼 때만 사용하고, 블루 발광 효과로 일반 콘텐츠를 강조하지 않는다. 모달 배경의 차폐는 `opacity.overlay` 기준을 사용하며 모달 자체는 불투명한 기본 표면으로 둔다.

## Shapes

모서리는 XS 6px, S 10px, M 16px, L 20px로 고정한다. 버튼·입력창·선택 상자는 S, 작은 배지는 XS, 펼친 선택 목록과 일반 컨테이너는 M, 큰 작업 영역과 모달은 L을 사용한다. 버튼 크기가 커져도 모서리 단계는 S로 유지한다. 기본 테두리 두께는 1px, 포커스 외곽선과 간격은 각각 2px이다. 컨트롤을 모두 각진 사각형이나 완전한 알약 형태로 통일하지 않는다.

## Icons

기본 아이콘은 **[Phosphor](https://phosphoricons.com/)**로 통일한다. 일반 동작에는 Regular, 선택·켜짐 상태에는 같은 계열의 Fill을 사용한다. 기본 색상은 주변 글자색을 따르며, 선택은 형태 변화와 블루 강조를 함께 사용한다. 서로 다른 라이브러리의 선형·채움 아이콘이나 이모지를 같은 역할에 섞지 않는다. 로고는 별도 브랜드 자산을 사용한다.

독립 아이콘은 20px, 보조 정보는 16px을 기본으로 한다. 버튼 안에서는 [컨트롤 크기표](components.md#shared-sizes)의 12·16·20px을 사용한다. Phosphor의 원본 256 × 256 좌표계와 Regular·Fill 자산을 유지하고 비율대로 축소한다. 다른 좌표계의 선 굵기 규격을 덮어씌우거나 개별 아이콘의 선을 임의로 조정하지 않는다.

| 동작 | Phosphor 이름 |
|---|---|
| 검색 | `magnifying-glass` |
| 추가 | `plus` |
| 목록 펼치기 | `caret-down` |
| 닫기·선택 해제 | `x` |
| 선택됨 | `check` |
| 더보기 | `dots-three` |
| 다운로드 | `download-simple` |
| 삭제 | `trash` |
| 복사 | `copy` |
| 다시 시도 | `arrow-clockwise` |
| 정렬 | `arrows-down-up` |
| 전송 | `paper-plane-tilt` |
| 응답 생성 중단 | `stop` |
| 대화 | `chat-circle` |
| 차트 보기 | `chart-bar` |
| 표 보기 | `table` |

| 역할 | 형태와 사용 기준 |
|---|---|
| 검색·닫기·더보기·일반 도구 | Regular. 조작 아이콘끼리 형태와 시각적 무게 통일 |
| 현재 선택한 보기·켜진 동작 | 같은 이름의 Fill + 선택 배경 또는 글자 강조. 일반 동작을 무조건 Fill로 바꾸지 않음 |
| 12px의 작은 표시 | 단순한 형태와 Fill의 식별성을 우선 확인. 알아보기 어려우면 아이콘을 키우거나 문구 사용 |
| 내용을 설명하는 그래픽 | 필요할 때 별도 그래픽으로 정의. 도구용 아이콘에 임의의 다색·입체 효과를 추가하지 않음 |

당근 SEED의 [선형·채움 사용 기준](https://seed-design.io/docs/foundation/iconography/usage)을 역할 판단에 참고한다. 비즈렌즈는 Phosphor의 일관된 Regular·Fill 체계를 공통 규격으로 채택한다. 아이콘 계열을 화면별로 선택하지 않는다. Phosphor의 MIT 저작권·허가 고지를 보존한다.

아이콘은 의미 전달이나 탐색 속도에 도움이 될 때만 붙인다. 모든 제목·버튼·상태에 반복해서 넣거나 AI를 나타내기 위한 반짝이 장식을 추가하지 않는다. 단독 아이콘 버튼에는 ‘검색’, ‘질문 전송’처럼 동작을 설명하는 접근 가능한 이름을 제공하고, 장식용 SVG는 읽기 순서에서 제외한다. 터치 영역은 아이콘의 그림 크기와 별개로 최소 44px을 확보한다.

## Motion

모션은 눌림·등장·퇴장·상태 변화를 이해시키기 위한 공통 규격이다. 기본 값 `motion.duration.fast`(150ms)·`normal`(200ms) 위에 `press`·`menu`·`enter`·`exit`·`message` 역할을 연결한다. 등장과 퇴장의 가속도, 작은 이동 거리, 누름 축소도 역할 토큰으로 정의한다.

동작별 시간·거리·중단·동작 줄이기 기준은 [모션 가이드](motion.md)를 따른다. 라이브러리의 기본 스프링이나 등장 효과가 디자인 규격을 대신하지 않는다.

## Accessibility

입력·선택·메뉴·탭은 키보드로 조작할 수 있어야 한다. 오류·처리 결과는 화면 읽기 도구에도 전달하고 색상 변화만으로 알리지 않는다.
