# AI & Conversation

[디자인 개요](../DESIGN.md) · [시스템 구조](system.md) · [기초 스타일](foundations.md) · [컴포넌트](components.md) · [사용 패턴](patterns.md)

AI 대화에서 메시지·입력·처리 상태·근거·결과 적용을 표현하는 공통 기준이다. 기본 색상·서체·버튼·입력창은 기존 기준을 재사용하며, AI 전용 장식이나 별도의 색상 체계를 추가하지 않는다.

업무 맥락을 이해하는 친절한 도우미처럼 표현한다. 채널톡의 PC 대화·상세 영역 분리와 뤼튼의 답변·도구 구분을 참고하며, 일반 입력 폼을 넓게 늘린 형태로 대화창을 만들지 않는다. 말투는 자연스러운 해요체, 내용은 핵심부터 전달한다.

## Layout and Hierarchy

- 독립적인 대화 작업에는 전체 대화 영역, 다른 내용을 보면서 질문하는 경우에는 보조 패널을 사용한다. 구체적인 배치는 해당 화면의 작업 흐름에 맞춰 결정한다.
- 현재 대화의 제목과 참조 맥락 → 메시지 기록 → 입력 영역 순서로 구성한다. 좁은 화면에서 입력창이 내용이나 마지막 메시지를 가리지 않게 한다.
- 대화 전에는 실제 지원하는 작업과 예시 질문을 간결하게 안내한다. 지원하지 않는 기능을 제안하거나 대화가 곧 데이터 변경을 뜻하는 것처럼 표현하지 않는다.
- 사용자의 질문, AI 응답, 실제 작업 결과는 작성 주체와 상태를 구분한다. 색상만으로 역할을 구분하지 않고 이름이나 역할 표시를 함께 제공한다.

### Visual Composition

- 시작 전에는 짧은 제목·입력창·필요한 예시 질문만 제공한다. 인사말을 가짜 첫 응답으로 채우거나, 비어 있는 메시지 영역의 높이를 미리 확보하지 않는다.
- 대화 본문은 기본 표면, 패널 주변과 시작 화면은 옅은 중립 표면으로 부드럽게 구분할 수 있다. 큰 테두리 상자 안에 헤더·메시지·입력창을 다시 나누는 구성을 기본으로 삼지 않는다. 독립 패널의 실제 경계가 필요한 경우에만 바깥 구분을 둔다.
- 대화 본문과 입력창은 같은 폭으로 정렬하며 독립 화면에서는 최대 760px을 기준으로 한다. 좁은 화면에서는 가용 폭을 사용한다. 짧은 안내를 넓은 화면 끝까지 늘리지 않는다.
- 사용자 질문은 오른쪽의 작은 옅은 블루 말풍선, 응답은 왼쪽의 열린 본문으로 구분한다. 말풍선은 M 모서리와 12px·16px 내부 여백을 사용한다. 역할 이름은 접근 가능한 형태로 제공하고 같은 라벨을 시각적으로 반복하지 않는다. 응답 시작에는 한 가지 선형 대화 아이콘을 작은 중립 표면 위에 사용할 수 있다.
- 시작 제목과 설명 사이는 12px, 설명과 입력창 사이는 24px, 입력창과 예시 질문 사이는 16px을 기본으로 한다. 대화 턴 사이는 32px로 두며 본문 문단 간격보다 넓게 둔다.
- 자료와 조건을 모든 답변 하단의 펼치기·배지·주석으로 반복하지 않는다. 현재 참조 자료와 조건은 대화 상단에서 한 번 확인하게 하고, 답변 본문은 질문에 대한 내용에 집중한다. 초기 안내에는 출처·복사·평가 같은 응답용 도구를 표시하지 않는다.
- 특정 주장이나 수치의 출처를 확인해야 할 때에는 해당 내용에서 실제 자료로 연결한다. 답변마다 추상적인 ‘근거와 조건 보기’ 동작을 자동으로 추가하지 않는다. 자료 확인은 해당 화면에서 실제 제공하는 문서·데이터 조회 흐름과 연결한다.
- 안내·조건·상태를 모두 배지로 만들지 않는다. 참조 맥락은 한 줄의 보조 정보로 정리하고 변경 가능한 항목만 컨트롤로 표현한다.

## Messages

| 역할 | 표현 | 사용 기준 |
|---|---|---|
| 사용자 | `selection.background` 배경 + `text.primary` 글자 | 질문을 짧은 독립 영역으로 구분. 긴 메시지를 진한 블루로 채우지 않음 |
| AI | `surface.default` 배경 + `text.primary` 글자 | 제목·문단·목록·표로 읽기 구조 제공. 모든 응답을 중첩 카드로 감싸지 않음 |
| 작업 상태·결과 | 상태 이름 + 필요한 상태색 | AI의 설명과 실행 시스템의 실제 결과를 구분 |

메시지 본문은 [기초 서체 기준](foundations.md#typography)의 `type.body`를 사용한다. 기본 컨트롤의 짧은 라벨과 달리 긴 문장을 읽는 영역이므로 본문 크기를 적용한다. 응답 안의 표·수치·차트는 [정보 표현 기준](patterns.md#information-and-data)을 따른다.

- 생성한 내용과 사용자가 입력한 내용을 원문에 맞게 구분한다. 인용·코드·표의 경계를 명확하게 표시한다.
- 먼저 질문에 답하고 필요한 이유·비교·다음 행동을 이어 쓴다. 단순 답변에도 제목과 불릿 목록을 강제로 만들지 않는다. ‘다음과 같습니다’ 같은 도입을 매번 반복하지 않는다.
- 복사·다시 응답·피드백은 필요한 응답에 보조 동작으로 제공한다. 대화 영역에서 전송·적용보다 강하게 강조하지 않는다.
- 복사는 화면에 표시된 내용을 대상으로 하며, 응답 재생성으로 기존 결과를 조용히 덮어쓰지 않는다. 여러 결과가 생기면 현재 보고 있는 결과를 식별할 수 있게 한다.
- AI가 답한 내용과 실제 완료 상태는 구분한다. 실행 결과를 확인하기 전에는 ‘저장 완료’ 같은 확정 표현을 사용하지 않는다.

## Composer

기본 형태와 버튼 크기는 [공통 컴포넌트](components.md)를 따른다. 입력 본문은 `type.body`로 읽기 편하게 두고, 내용에 따라 여러 줄로 늘어나게 한다. 과도하게 길어지면 입력 영역 안에서 스크롤하되 전송과 중단 동작은 보이게 유지한다.

입력창의 표면·경계·호버·포커스는 [입력 계열 공통 규칙](components.md#inputs-and-selects)을 따른다. M 모서리·16px 내부 여백으로 표현하고, 내부 텍스트 영역에 별도의 테두리나 포커스 외곽선을 중복하지 않는다. 초기에는 한두 줄 입력에 맞는 높이로 시작하고 내용이 늘면 확장한다. 전송 버튼과 예시 질문은 M 크기를 사용하며, 예시 질문은 중립색 채움으로 낮게 강조한다. 예시 질문을 작은 밑줄 링크로 나열하지 않는다.

- 입력 목적을 알 수 있는 접근 가능한 이름을 제공한다. 안내 문구는 실제로 지원하는 입력 방식만 설명한다.
- Enter는 전송, Shift+Enter는 줄바꿈을 기본으로 한다. 한글 등 입력기 조합 중 Enter는 전송으로 처리하지 않는다. 터치 환경에서는 보이는 전송 버튼을 제공한다.
- 빈 메시지나 준비되지 않은 입력은 전송할 수 없게 한다. 전송이 접수되기 전 입력을 잃지 않도록 한다.
- 생성 중에는 전송 위치에 ‘응답 중단’을 제공한다. 새 질문 초안은 작성할 수 있게 보존하고, 후속 전송은 현재 요청이 끝나거나 중단된 뒤 가능하게 한다. 별도 대기열은 정의하지 않는다.
- 대화 초기화·새 대화는 전송과 떨어진 보조 동작으로 둔다. 새 대화를 시작할 때 전송하지 않은 초안은 기본적으로 보존한다. 작업상 초안을 지워야 하면 손실을 분명히 알린다.

## Context and Evidence

- 현재 참조하는 자료나 선택 조건이 있다면 대화 상단에 14px의 이름·값으로 한 번 표시한다. 실제로 변경할 수 있는 조건만 컨트롤로 제공하고 처리 준비 전에는 준비 완료로 표시하지 않는다.
- 어떤 맥락으로 생성한 응답인지 나중에도 식별할 수 있게 한다. 이후 참조 맥락을 바꾸더라도 이전 답변의 근거가 소급해서 바뀐 것처럼 보이지 않게 한다.
- 데이터에 기반한 답변은 확인 가능한 출처·조건·기준으로 연결한다. 계산 결과와 AI의 해석·제안은 구분한다.
- 근거가 없거나 정보가 부족하면 그 범위와 필요한 추가 정보를 설명한다. 임의의 출처·신뢰도 퍼센트·진행률을 만들어 표시하지 않는다.
- 사용자의 판단에 필요한 제한은 해당 결과 가까이에서 설명한다. 모든 응답에 긴 경고를 반복해 내용을 밀어내지 않는다.

## Generation and Execution States

| 상태 | 표시 | 가능한 동작 |
|---|---|---|
| 전송 대기 | 메시지 접수·대기 중임을 표시 | 전송 중복 방지, 가능한 경우 요청 취소 |
| 응답 생성 | 실제 도착한 내용부터 표시 | 응답 중단, 초안 작성 |
| 작업 실행 | 실제 실행 중인 작업과 상태 표시 | 지원하는 경우 작업 취소. 응답 중단과 구분 |
| 완료 | 완성된 응답과 확인된 실행 결과 표시 | 복사·후속 질문·필요한 결과 확인 |
| 중단 | 부분 응답과 ‘중단됨’ 표시 | 후속 질문 또는 재시도 |
| 실패 | 실패 범위와 이유·복구 경로 표시 | 입력 보존, 안전한 재시도 |

- ‘분석 중’, ‘자료 확인 중’ 등 단계 표시는 실제 시스템 동작을 반영할 때만 사용한다. 내부 추론을 단계별로 재현한 것처럼 표현하지 않는다.
- 응답 중단은 텍스트 생성을 멈추는 동작이다. 이미 시작된 작업의 취소·원상복구가 보장되는 것으로 표현하지 않는다.
- 응답 생성과 작업 실행이 끝난 시점은 별도로 판단한다. 생성이 끝났어도 실행 중인 작업을 완료로 바꾸지 않는다.
- 사용자가 최신 응답을 보고 있을 때만 새 내용을 따라 스크롤한다. 이전 메시지를 읽는 중에는 위치를 유지하고 ‘새 응답 보기’ 동작을 제공한다.
- 화면 읽기 도구에는 상태 변화와 완료를 전달하되, 생성되는 모든 글자를 반복해서 읽어 탐색을 방해하지 않는다.
- 새 메시지는 [모션 규격](motion.md)의 150ms·4px 등장 효과를 한 번만 사용한다. 스트리밍 글자마다 효과를 반복하지 않는다. 대화 패널은 등장 250ms·퇴장 150ms를 사용하고, 닫는 동안에도 초안과 대화 기록은 보존한다.

## Applying Results

- 설명·제안·변경 미리보기·적용 완료를 별도 단계로 표현한다. 대화 응답 자체를 실제 변경 완료의 증거로 삼지 않는다.
- 변경 작업에는 대상·범위·예상 결과를 보여준다. [변경과 복구 원칙](patterns.md#changes-and-recovery)에 따라 자동 반영과 명시적 적용을 구분한다.
- 손실 위험이 있는 변경은 적용 전에 확인을 제공하고, 되돌릴 수 있으면 실행 취소 경로를 제공한다.
- 적용한 결과에는 실제 반영 여부를 확인할 수 있는 상태와 결과 위치를 제공한다. 버튼의 로딩 종료만으로 완료를 암시하지 않는다.
- 재시도·응답 재생성은 이미 실행한 작업을 자동으로 다시 실행하지 않는다. 중복 실행 가능성이 있으면 현재 결과를 먼저 확인하고 필요한 동작을 구분한다.

## Failure and Recovery

- 전송 실패, 응답 생성 실패, 작업 실행 실패를 구분한다. 오류는 영향을 받은 메시지나 작업 가까이에 표시한다.
- 실패하더라도 입력한 질문·참조 맥락·확인 가능한 기존 결과를 유지한다. 부분 응답은 완료된 답변과 구분한다.
- 필요한 정보가 부족한 경우 추가 질문으로 범위를 좁힌다. 권한·연결·사용 제한 문제를 단순히 ‘AI가 답변하지 못함’으로 뭉뚱그리지 않는다.
- 재시도할 수 없으면 가능한 다음 행동을 안내한다. 토스트만으로 대화 오류를 설명하지 않는다.
