# Patterns

[디자인 개요](../DESIGN.md) · [시스템 구조](system.md) · [기초 스타일](foundations.md) · [컴포넌트](components.md) · [AI 대화](ai-conversation.md)

컴포넌트를 언제 선택하고 어떻게 조합하는지 정의한다. 제품 목록이나 특정 화면의 기능 구성을 정의하지 않는다. 크기·서체·색상값은 컴포넌트와 기초 스타일의 기준을 따른다.

## Hierarchy

같은 목적의 동작이 모인 작업 영역에서 가장 중요한 동작 하나를 강조한다. 서로 독립적인 영역도 시각적 강조를 경쟁시키지 않는다. 제목과 현재 맥락 → 필요한 조건과 동작 → 주요 내용 → 보조 설명 순서를 기본으로 한다.

## Content First

화면에 넣을 수 있는 정보와 처음부터 보여야 하는 정보를 구분한다. 사용자의 현재 판단이나 행동에 필요하지 않으면 기본 화면에서 제외한다.

| 영역 | 처음 보여줄 내용 | 필요할 때 여는 내용 |
| --- | --- | --- |
| 자료 목록 | 제목, 발행처와 날짜, 검색 | 추가 검색 조건, 수집 경위 |
| 내용 읽기 | 제목, 발행 정보, 읽을 내용 | 내용을 제공한 사이트로 이동하는 동작 |
| 키워드 입력 | 이름, 검색할 말, 저장 | 채널과 자동 수집의 세부 설정 |
| 처리 결과 | 완료 여부 또는 지금 필요한 복구 행동 | 상세한 처리 기록 |

- 제목이나 내용 행을 누르는 동작이 있으면 같은 목적의 ‘보기’ 버튼을 반복하지 않는다.
- 제목만으로 목적이 명확하면 설명 문장을 생략한다. 안내 문구는 사용자의 결정에 필요한 때만 해당 위치에 둔다.
- 모든 행에 수집 상태·요약·버튼·배지를 동시에 붙이지 않는다. 요약은 읽는 화면에서 제공하고, 상태는 수집 관리 맥락에 둔다.
- 설명과 입력 조건을 접기·펼치기 영역으로 감싸지 않는다. 폴더 탐색 트리에서는 계층 탐색을 위한 펼침·접힘 버튼을 사용한다.
- 정보를 덜 보여주기 위해 글자를 줄이지 않는다. 중요하지 않은 정보의 노출 위치를 바꾼다.
- 사용자 판단이나 행동에 필요하지 않은 기술 설명과 면책 문장은 삭제한다. 불필요한 문장을 도움말로 옮겨 보존하지 않는다. 도움말은 입력 기준·선택의 차이처럼 실제 결정에 필요한 정보에만 사용한다.

## Folder Navigation

폴더 아래에 하위 폴더와 태그를 한 트리로 표시한다. 폴더 깊이에 제한을 두지 않으며 같은 폴더에서 하위 폴더와 태그가 함께 존재할 수 있다. 태그는 자식이 없는 노드이며 한 태그를 여러 폴더에서 표시할 수 있다. 폴더·태그 이름과 함께 현재 자료 유형에 해당하는 연결 자료 수를 표시한다.

- 폴더 이름 클릭은 하위 폴더를 포함한 자료 조회, 태그 이름 클릭은 해당 태그 자료 조회로 구분한다.
- 펼침·접힘 버튼은 표시 상태만 바꾸고 선택·조회 상태를 바꾸지 않는다.
- 폴더 아이콘과 태그 아이콘, 들여쓰기, 선택 상태로 계층과 현재 위치를 구분한다.
- 자료 ID는 캐시·데이터 식별에, 경로별 행 키는 포커스·선택 상태에 사용한다.
- 폴더·태그 목록과 개수는 페이지네이션 없이 한 번에 조회한다. 펼칠 때 같은 메타데이터를 다시 요청하지 않는다.
- 항상 보이는 생성 폼 대신 새 폴더 버튼과 행별 관리 동작을 사용한다. 입력은 필요한 때 열고 완료 후 해당 행으로 돌아온다.
- 폴더 이동은 폴더 행을 직접 끌어 다른 폴더나 최상위에 놓는 방식으로 제공하며 이동 대화상자를 요구하지 않는다. 이동은 지정한 연결만 변경하며 태그·자료와 다른 폴더 연결을 보존한다.
- 폴더 행과 빈 영역의 우클릭 메뉴는 행 메뉴와 같은 동작을 제공한다. 폴더 삭제는 하위 폴더를 포함하되 태그·자료를 보존하며, 남은 폴더 연결이 없는 태그는 미분류에 표시한다.
- 이벤트 연결 대상 선택에서도 같은 폴더 트리를 재사용한다. 화면 목적에 따라 선택과 관리 동작을 구분한다.
- 앱 사이드바를 접어도 메뉴 아이콘의 가로·세로 위치를 유지한다.
- 수집 자료 작업 화면은 회색 바깥 캔버스와 카드 여백 없이 흰색 전체 폭을 사용한다. 화면 제목은 상단 헤더에 둔다.

## User Language

분석 담당자가 익숙한 대상과 행동으로 표현한다. 내부 데이터 계층이나 수집 기술을 화면에서 설명하지 않는다.

| 내부 표현 | 사용자에게 필요한 표현 |
| --- | --- |
| 원문 / 원문 URL | 기본 목록에서 생략. 이동이 필요할 때 ‘기사 보기’ 또는 ‘게시글 보기’ |
| 본문 확보 / 목록 확보 | 기본 자료 화면에서 생략. 수집 관리에서 필요한 상태만 안내 |
| 규칙 / definition | 키워드, 검색어 |
| Worker / Pool / Dispatcher | 수집 환경. 일반 자료 화면에서 생략 |
| 증분 / cursor | 새 자료, 마지막 수집 이후 |
| version | 변경 이력. 설정의 추가 정보로 제공 |

같은 행동을 ‘원문 보기’, ‘내용 보기’, ‘자세히 보기’로 번갈아 부르지 않는다. 자료 제목을 누르면 읽는다는 기본 동작을 유지한다. 별도 사이트로 이동하는 경우에만 이동 버튼의 이름으로 대상이 기사인지 게시글인지 알려준다.

## Reference Application

국내의 익숙한 표현을 다음 부위별 기준으로 적용한다. 이 표는 관찰한 화면을 바탕으로 정한 비즈렌즈의 설계 규칙이며, 모든 국내 서비스가 같은 형태를 사용한다는 뜻은 아니다.

| 부위 | 참고하는 사례와 관찰 | 비즈렌즈 적용 | 피할 구성 |
|---|---|---|---|
| 전체 작업 영역 | 채널톡 PC 수신함의 목록·대화·상세 구분 | 탐색 메뉴·주요 내용·필요한 보조 패널의 역할 분리. 보조 패널은 사용자가 열고 닫기 가능 | 모든 내용을 카드 그리드에 같은 크기로 배치 |
| 메뉴·탭 | 당근 커뮤니티의 상위 탭과 세부 조건 구분 | 상위 위치는 메뉴·탭, 보기 모드는 분할 선택, 조회값은 필터로 표현 | 메뉴·탭·필터를 같은 작은 배지로 처리 |
| 제목·도구 | 토스 주요 값과 가까운 실행, 당근 상세 하단 실행 | 제목 24px, 짧은 설명 16px. 관련 주요 실행은 제목 우측 또는 작업 끝에 배치 | 큰 제목 아래 설명·배지·도구 줄을 중복 배치 |
| 입력·선택 | 당근 SEED 버튼 강조와 선택 컨트롤 | 흰 입력·옅은 조건 영역·10px 모서리. 라벨·선택값·도움말을 읽기 쉬운 한 필드로 구성 | 진한 외곽선과 브라우저 기본 선택 목록을 그대로 노출 |
| 조건·결과 | 네이버 데이터랩의 조건 구성과 조회, 토스 증권의 기준 표시 | 조건 묶음 → 조회 → 적용 범위·결과 건수 → 결과 도구 → 본문 | 입력 중인 값과 현재 결과의 조건 혼동 |
| 목록·표 | 토스 계좌 행, 당근 목록의 제목·값·메타정보 | 제목·주요 값·설명·동작의 위치 고정. 수치 비교는 표, 내용 탐색은 목록 | 행마다 카드·다색 상태 배지 반복 |
| 요약·차트 | 토스 증권의 주요 값과 비교 정보 구분 | 관련 핵심 값은 하나의 요약 행. 차트와 정확한 수치는 같은 맥락에서 연결 | 같은 수치를 카드·차트·설명으로 중복 강조 |
| 안내·상태 | 당근·토스의 짧은 실행 문구와 낮은 강조 보조 동작 | 필드 도움말·오류·복구는 14px, 해요체. 완료는 짧은 토스트나 결과 변화 | 각주와 긴 면책 문구를 여러 위치에 반복 |
| 대화·보조 작업 | 채널톡 PC 대화 영역, 뤼튼 본문과 응답 도구 | 현재 대상 상단, 자연스러운 본문, 옅은 질문 말풍선, 입력 하단. 통계·원본을 보며 질문 가능 | 거대한 빈 대화 상자, 기본 삼각형 펼치기, 반복 근거·조건 주석 |

출처는 [주요 레퍼런스](#primary-references)와 [데이터 작업 레퍼런스](#secondary-references-for-data-tasks)에 연결한다. 치수·토큰은 [기초 스타일](foundations.md)과 [컴포넌트](components.md)에 정의한다.

## Action Hierarchy

### Familiar Interaction Hierarchy

국내의 익숙한 서비스 표현을 업무 화면에 적용할 때는 색상이나 둥근 모서리보다 다음의 위계를 우선한다.

| 역할 | 기본 표현 | 배치 기준 |
|---|---|---|
| 가장 중요한 실행 | 강조색 채움·짧은 동작명 | 현재 작업 영역에서 하나를 우선 노출 |
| 보조 실행 | 옅은 중립 채움·진한 글자 | 주요 버튼과 가까이 두되 같은 강도로 경쟁하지 않음 |
| 세부 동작 | 텍스트·더보기 | 반복 행의 우측이나 관련 정보 가까이 배치 |
| 주요 정보 | 진한 제목·값 | 먼저 읽는 위치에 정렬하고 글자 위계로 강조 |
| 보조 정보 | 중립색의 짧은 설명 | 제목 아래 또는 값 가까이 배치 |
| 반복 상태 | 중립 텍스트·필요한 약한 배지 | 색상 종류를 늘리지 않고 같은 자리에서 비교 가능하게 표시 |

당근 SEED의 강조 수준 구분과 반복 배지의 낮은 주목도, 토스 TDS의 fill·weak 구분을 참고한다. 화면을 전부 무채색으로 만들거나 모든 동작을 테두리 버튼으로 바꾸는 방식으로 단순화하지 않는다. 컨트롤의 경계와 포커스는 인지 가능하게 유지한다.

### Grouping Actions

- 기본 버튼 묶음은 보조 동작 왼쪽, 주요 동작 오른쪽 순서로 배치한다. 우측 정렬을 기본으로 하며, 좁은 화면에서도 두 동작이 충분히 들어가면 같은 행을 유지한다. 세로로 쌓아야 하면 주요 동작을 위에 두고 보조 동작을 아래로 배치하며 실제 탐색 순서도 함께 맞춘다. 시각 순서만 CSS로 뒤집지 않는다.
- 한 묶음에 주요 버튼은 하나만 둔다. 동등한 보조 동작은 같은 강조 수준을 사용한다. 동작이 많으면 주요 동작과 자주 쓰는 보조 동작만 노출하고 나머지는 메뉴로 모은다.
- 삭제 같은 위험 동작은 일반 동작과 간격 또는 메뉴 구분선으로 분리한다. 진입 버튼을 항상 빨갛게 채우지 않고, 최종 손실을 확정할 때 위험 강조를 사용한다.
- 링크는 위치 이동, 버튼은 동작 실행에 사용한다. 단순 페이지 이동에 주요 채움 버튼을 남발하지 않는다.
- 문구는 ‘확인’보다 ‘저장’, ‘삭제’, ‘적용’처럼 실행 결과가 드러나는 동작명을 우선한다.
- 아이콘 전용 버튼에는 동작 이름을 제공한다. 툴팁은 보조 설명이며 이름을 대신하지 않는다.

## Choosing a Control

| 필요 | 기본 선택 | 구분 기준 |
|---|---|---|
| 여러 항목 선택 | 체크박스 | 0개 이상 선택할 수 있는 독립 항목 |
| 한 항목 선택 | 라디오 또는 선택 상자 | 적은 수의 옵션을 비교해야 하면 라디오, 많거나 공간이 좁으면 선택 상자 |
| 즉시 켜기·끄기 | 스위치 | 별도 저장 없이 즉시 반영되는 독립 설정. 제출 전 동의에는 체크박스 사용 |
| 같은 맥락의 보기 전환 | 탭 또는 분할 선택 | 콘텐츠 영역을 바꾸면 탭, 짧은 보기·정렬 모드를 바꾸면 분할 선택 |
| 적용된 조건 표시·해제 | 필터 Chip | 현재 선택을 표시하고 개별 해제 가능. 작업 실행 버튼과 구분 |
| 상태·분류 표시 | 배지 | 읽기 전용 표시. 배지를 버튼처럼 보이게 만들지 않음 |
| 가능한 동작 목록 | 메뉴 | 실행 항목의 모음. 값 선택용 선택 상자와 구분 |

옵션의 개수만으로 결정하지 않고 비교 필요성, 설명 길이, 선택 빈도를 함께 고려한다. 탭 이동·정렬·필터 변경은 저장 완료와 같은 알림을 매번 띄우지 않는다.

## Input and Validation

- 라벨은 항상 표시하고 placeholder로 대체하지 않는다. 단위·형식·제한은 입력 전에 알 수 있게 둔다.
- 필수·선택 표시 방식은 폼 안에서 통일한다. 오류는 해당 필드 아래에 이유와 수정 방법을 표시하고 입력한 값을 보존한다.
- 입력 도중 불완전한 값만으로 바로 오류를 띄우지 않는다. 기본은 필드를 벗어나거나 제출할 때 검증하고, 오류가 확인된 필드는 수정하면서 해소 상태를 반영한다.
- 제출 실패 시 첫 오류로 안내하고, 오류가 많으면 상단 요약에서 해당 필드로 이동할 수 있게 한다.

## Information and Data

### Query and Result Hierarchy

조회·목록 화면에서는 다음 순서를 기본으로 한다.

1. **화면 맥락:** 제목·필요한 현재 위치·짧은 설명
2. **조회 조건:** 검색어·기간·분류 등을 한 영역으로 묶고 조회·초기화 동작 배치
3. **결과 도구:** 결과 건수는 왼쪽, 정렬·표시 개수·내려받기 등 결과에 대한 조작은 오른쪽
4. **목록·통계표:** 제목·헤더·행 구분선을 중심으로 연속 배치
5. **후속 탐색:** 목록 아래 페이지 이동, 필요한 상세·보조 정보는 인접 영역에서 제공

기간·분류처럼 여러 조건을 함께 구성하는 조회는 명시적 조회 동작을 기본으로 한다. 입력 중인 조건과 현재 결과에 적용된 조건을 구분하고 결과 옆에는 적용된 조건을 표시한다. 단순 목록의 즉시 검색은 결과 갱신 비용과 사용 맥락이 허용할 때만 사용한다.

행과 열의 의미를 비교하는 표를 개별 카드로 쪼개지 않는다. ‘완료·검토 중’ 같은 반복적인 진행 상태는 중립 텍스트로 두고, 주의·오류가 있는 행에만 추가 단서를 제공한다. 여러 색 배지로 표의 모든 행을 강조하지 않는다.

### Choosing a Representation

- 목록은 항목을 빠르게 탐색할 때, 표는 같은 속성을 행끼리 비교할 때, 카드는 서로 다른 구조의 내용을 독립 단위로 보여줄 때 사용한다. 단순 여백 확보를 위해 카드를 추가하지 않는다.
- 검색·필터 결과에는 결과 개수와 적용 조건을 유지한다. 조건 해제와 전체 초기화를 구분하고, 조건 변경 시 결과 및 페이지 위치의 변화를 예측할 수 있게 한다.
- 차트는 비교·추세·분포 등 관계를 보여줄 때 사용하고 정확한 수치는 라벨·툴팁·표로 확인할 수 있게 한다. 핵심 값이 마우스 호버에서만 보이게 하지 않는다.
- 범주 비교에는 막대, 시간 흐름에는 선, 구성비에는 합계와 부분의 관계가 드러나는 표현을 우선 검토한다. 막대의 값 축은 0을 기본으로 하고, 다른 기준이 필요한 표현에는 축과 범위를 명시한다.
- 데이터의 단위·기간·기준·결측은 명시한다. 데이터 없음, 값 0, 계산 불가는 별도 상태로 표시한다.

## Layout and Density

- 제목·도구 모음·본문의 시작선을 맞춘다. 제목과 설명은 8px, 제목 영역과 주요 내용은 24px 간격을 사용한다.
- 화면 안쪽 여백은 기본 24px, 좁은 화면에서는 16px을 사용한다. 긴 문단의 읽기 폭은 약 65–75ch로 제한하되 표·차트에는 이 제한을 강제하지 않는다.
- 기본 정보 밀도는 M이다. 반복 행과 보조 도구에만 S를 사용하며, 글자를 줄여 공간을 억지로 맞추지 않는다.
- 좁은 화면에서는 보조 영역을 본문 아래로 옮기고 도구 모음을 줄바꿈한다. 핵심 동작은 보이게 유지하며, 보조 동작은 더보기 메뉴로 모을 수 있다.
- 표처럼 구조 보존이 필요한 영역에만 내부 가로 스크롤을 허용한다. 화면 전체가 가로로 밀리지 않도록 한다. 반응형 전환은 내용이 겹치기 전에 이루어지며 글자 크기 축소로 대체하지 않는다.
- 주요 내용은 가용 폭 안에서 최대 1280px, 독립 대화 본문은 최대 760px을 기준으로 한다. 보조 패널은 기본 368px이며, 주요 내용의 가독성이 부족해지면 한 열로 전환한다. 화면별로 임의의 패널 폭을 늘리지 않는다.
- 관련 핵심 값은 같은 요약 행에서 비교하고 값마다 카드를 만들지 않는다. 요약과 상세의 간격은 32px, 상세 안의 제목과 내용은 16px 또는 24px을 사용한다.

## Tone and Guidance

- 설명은 짧고 자연스러운 해요체로 작성한다. 버튼·메뉴·표 헤더는 간결한 동작명과 항목명을 사용한다.
- 안내는 이유와 다음 행동을 연결한다. ‘조회 결과 없음’ 대신 ‘조건에 맞는 응답이 없어요. 기간이나 대상을 바꿔보세요’처럼 작성한다.
- 처리 실패는 사용자의 잘못처럼 표현하지 않는다. 보존된 입력과 다시 할 수 있는 행동을 알려준다.
- ‘성공적으로 수행되었습니다’, ‘요청 사항을 입력하십시오’ 같은 시스템 중심의 문구를 기본으로 사용하지 않는다. 친근함을 위해 불필요한 감탄·이모지·긴 인사를 추가하지 않는다.
- 필수 정보는 해당 작업 영역에 바로 표시하고, 불필요한 설명은 생략한다.

## Feedback and Overlays

| 전달할 내용 | 표현 | 동작 기준 |
|---|---|---|
| 특정 필드의 오류·도움 | 인라인 설명 | 관련 위치에 표시하고 수정·재시도 경로 제공 |
| 짧은 작업 완료 | 토스트 | 작업을 막지 않음. 사라져도 결과 확인 가능 |
| 영역·화면 전체에 영향 | 배너 또는 Callout | 영향 범위 가까이 유지하고 필요한 동작 제공 |
| 단어·아이콘의 보충 설명 | 툴팁 | 호버와 키보드 포커스로 접근. 필수 정보는 본문에 표시 |
| 현재 맥락의 짧은 추가 선택 | 팝오버 또는 메뉴 | 누른 요소 가까이 표시. 화면 밖으로 잘리지 않게 배치 |
| 집중이 필요한 짧은 작업·손실 확인 | 모달 | 관련 작업을 마칠 때까지 배경 조작 제한 |
| 비교하면서 보는 보조 상세 | 사이드 패널 | 원래 맥락을 유지. 좁은 화면에서는 별도 영역이나 전체 화면으로 전환 |

- 단순 성공 안내나 긴 편집 화면에 모달을 사용하지 않는다. 되돌릴 수 있는 작업은 확인창보다 실행 취소를 우선 검토한다.
- 모달에는 목적이 분명한 제목, 필요한 설명, 주요·보조 동작을 둔다. 일반 모달은 Escape와 명시적 닫기를 제공한다. 미저장 변경이나 손실 위험이 있으면 배경 클릭으로 조용히 닫히지 않게 한다.
- 모달이 열리면 내부로 포커스를 옮기고 내부에서 키보드 탐색을 유지하며, 닫으면 원래 실행 위치로 돌려준다. 툴팁·메뉴·팝오버도 Escape로 닫을 수 있게 한다.
- 토스트에 유일한 오류 설명이나 필수 확인을 맡기지 않는다. 동작이 포함된 알림은 읽기 전에 사라지지 않도록 충분한 시간과 접근 경로를 제공한다.

## Loading, Empty and Error States

| 상태 | 표시와 다음 행동 |
|---|---|
| 최초 내용 로딩 | 구조를 아는 영역은 스켈레톤, 모르는 영역은 설명이 있는 진행 표시 |
| 버튼으로 시작한 처리 | 해당 버튼 안에서 진행 표시, 너비 유지, 중복 실행 차단 |
| 기존 결과 갱신 | 기존 맥락을 유지하며 갱신 중임을 표시. 새 결과로 오해하지 않도록 구분 |
| 아직 생성된 내용 없음 | 무엇이 필요한지 짧게 설명하고 시작 동작 제공 |
| 검색·필터 결과 없음 | 현재 조건을 유지하고 조건 수정·초기화 동작 제공 |
| 처리 실패 | 이유와 영향 범위를 설명하고 입력·조건을 보존한 재시도 제공 |
| 접근 권한 없음 | 권한 문제임을 명시하고 가능한 접근·요청 경로 안내 |

진행률은 실제로 측정할 수 있을 때만 수치로 표시한다. 스켈레톤·진행 표시가 실제 콘텐츠나 확정 결과로 오인되지 않게 한다. 오류 때문에 전체 화면을 빈 화면으로 바꾸지 않고 가능한 범위의 기존 내용을 유지한다.

## Changes and Recovery

- 비활성 항목만으로 조건을 설명하지 않는다. 실행할 수 없는 이유와 필요한 조건을 가까운 안내 문구로 제공한다.
- 자동 반영은 위험이 낮고 되돌릴 수 있는 변경에 사용한다. 여러 조건을 함께 확인해야 하거나 처리가 무거운 경우 명시적 ‘적용’ 동작을 제공한다. 같은 유형 안에서 두 방식을 임의로 섞지 않는다.
- 저장이 필요한 편집에는 저장 전·처리 중·저장 완료·실패를 구분한다. 변경을 잃는 이탈에만 확인을 요청하고, 일반 이동마다 확인창을 띄우지 않는다.

공공데이터·통계 사이트는 조회 조건과 결과의 구조를 참고하는 자료다. 시각적 인상·서체 밀도·버튼 형태·말투의 기준은 주요 소비자 서비스 레퍼런스와 비즈렌즈의 부드럽고 친절한 방향을 우선한다.

각 시스템의 치수나 전체 구성을 그대로 채택하지 않고 공통 사용 원칙을 참고한다.
