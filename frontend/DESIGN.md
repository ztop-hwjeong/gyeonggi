# BizLens Design

## Design Direction

**친절하게 안내하고, 편하게 조작하는 업무 서비스**를 지향한다. 업무의 정확성과 정보 밀도를 유지하면서 국내 소비자 서비스에서 익숙한 읽기 순서·부드러운 컨트롤·짧은 안내를 적용한다. 사용자를 관리자 화면의 조작자로만 대하지 않고, 처음 방문해도 다음 행동을 이해할 수 있게 설계한다.

고객이 매일 쓰는 서비스처럼 편안하고 잘 다듬어진 인상을 목표로 한다. 밝은 표면·둥근 형태·충분한 간격·자연스러운 안내·즉각적이고 부드러운 반응을 함께 사용한다. 업무용이라는 이유로 화면 전체를 회색·외곽선·밀집된 작은 글자로 구성하지 않는다. 블루는 주요 실행과 선택에 분명하게 남긴다.

밝고 부드러운 바탕 위에 흰 작업 영역을 두고, 둥근 컨트롤과 명확한 블루 강조를 사용한다. 정보는 글자·정렬·여백으로 구분한다. 선·작은 각주·상태 배지로 내용을 잘게 나누지 않고, 같은 작업의 내용은 자연스럽게 이어서 읽게 한다.

업무용 화면의 정보 밀도를 유지하면서 당근·토스의 공개 서비스와 디자인 가이드에서 확인한 익숙한 조작 위계를 참고한다. 주요 실행은 분명하게, 보조 동작은 옅은 중립 채움으로, 세부 정보는 글자와 여백으로 구분한다. 굵은 외곽선·색 배지·장식 아이콘으로 모든 항목을 강조하지 않는다.

참고하는 부위와 적용 규칙은 [레퍼런스 적용표](design/patterns.md#reference-application)에 연결한다. 토스·당근은 정보 위계와 실행, 채널톡은 PC 작업 영역과 대화 맥락, 뤼튼은 답변과 도구의 역할 구분에 한정해 참고한다. 표면·치수·브랜드 자산을 그대로 복제하지 않는다.

주요 실행에는 분명한 블루 채움을 사용하고, 현재 메뉴·링크·탭·포커스에도 역할에 맞는 블루를 사용한다. 선택 배경은 옅은 블루로 두고 글자·밑줄·체크 표시를 함께 사용한다. 넓은 데이터 채움은 낮은 채도로 유지한다. 일반 진행 상태는 중립 텍스트로, 조치가 필요한 주의·오류는 상태색으로 구분한다.

## Shared Principles

- UI에서는 역할 토큰을 사용하고, 새 역할이 필요하면 기존 토큰으로 표현 가능한지 먼저 확인한다.
- 넓은 채움에는 부드러운 데이터 색상을 사용하고, 진한 블루는 주요 동작과 선택 강조에 사용한다.
- 텍스트·배경 조합은 가독성을 유지하며, 색상만으로 상태나 데이터를 구분하지 않는다.
- 공통 서체와 역할별 글자 기준을 사용하며, 화면별로 서체나 크기를 임의로 추가하지 않는다.
- 아이콘은 Phosphor의 일반·선택 형태를 역할에 맞게 사용한다. 모션은 공통 시간·거리·가속도로 조작 결과를 전달하고 동작 줄이기 설정을 따른다.
- 자주 읽는 조건·도움말은 14px 이상으로 제공한다. 작은 각주를 늘리는 대신 내용의 위치와 길이를 먼저 정리한다.
- 안내와 대화는 짧고 자연스러운 해요체를 사용한다. 버튼은 ‘조회’, ‘저장’, ‘다시 시도’처럼 동작을 명확하게 표현한다.
- 버튼·입력창의 기본 크기는 M으로 유지하고, 밀도나 조작 환경에 따라 정해진 크기 단계만 사용한다.
- 화면을 만들 때는 크기를 고르기 전에 동작의 위계와 정보의 표현 목적에 맞는 컴포넌트를 고른다.
- 공통 규칙에서 벗어나는 경우 기존 기준으로 해결할 수 없는 이유와 재사용 범위를 먼저 확인한다.
- 다크 테마는 아직 정의하지 않았다. 밝은 테마를 임의로 반전해 사용하지 않는다.

## Document Boundaries

기초 스타일 → 컴포넌트 → 사용 패턴 순서로 공통 기준을 재사용한다. AI 대화 가이드는 이 기준을 적용하며 별도의 버튼·서체·색상 체계를 만들지 않는다.

같은 규격을 여러 문서에 다시 정의하지 않는다. 토큰은 실제 값을, 문서는 역할과 사용 조건을 정의한다. 화면별 작업 흐름과 배치는 해당 화면의 설계에서 다루며 공통 문서에 제품 목록을 넣지 않는다.
